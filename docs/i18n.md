# Internationalization (PT-BR / EN)

The web app uses a small built-in i18n layer in `src/i18n.tsx`.

## Defaults

- Primary/default language: **Português (Brasil)** (`pt-BR`)
- Secondary language: **English** (`en`)
- The browser language does **not** override the default.
- A manual language choice is persisted in `localStorage` using `chibi.language`.
- `document.documentElement.lang` is updated whenever the language changes.

## Using translations

Import the hook:

```tsx
import { useI18n } from "../i18n";

const { t, language, locale } = useI18n();
```

Render a string:

```tsx
<h1>{t("home.title.line1")}</h1>
```

Interpolation:

```tsx
<span>{t("search.results", { count: results.length })}</span>
```

## Adding a new string

1. Add the key to the `pt-BR` dictionary.
2. Add the same key to the `en` dictionary.
3. Replace hard-coded UI copy with `t("your.key")`.

Portuguese is the fallback. If a key is missing from English, the PT-BR value is used before falling back to the key name.

## Language selector

`LanguageSwitcher` is exported by `src/i18n.tsx` and currently mounted in the global topbar.

## Adding another language later

1. Add the language code to the `Language` union.
2. Add a matching dictionary to `messages`.
3. Add an option to `LanguageSwitcher`.
4. Map the language to the appropriate locale in `I18nProvider`.

Keep gameplay/API identifiers untranslated. Translate only user-facing interface copy.
